## Reproduce From GitHub

Use this sequence when rebuilding the session project from the pushed repository:

```bash
git clone git@github.com:zwangab91/trading.git
cd trading
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -e ".[dashboard,backend,test]"
.venv/bin/python -m trading_agent demo-summary --refresh-data
.venv/bin/python -m unittest discover
cd frontend
npm install
npm audit
npm run typecheck
NEXT_TELEMETRY_DISABLED=1 npm run build
```

Expected behavior:

- `.venv/` is recreated locally from `pyproject.toml`.
- `trading_agent.egg-info/` is regenerated by editable install.
- `var/market_data/yahoo_close_prices.csv` is regenerated by `demo-summary --refresh-data`.
- `var/audit.sqlite3` is recreated by `python3 -m trading_agent init-db`.
- `backend/app/main.py` exposes FastAPI endpoints for policy, dashboard summary, strategy detail, trades, and explicit Yahoo refresh.
- `frontend/` builds a Next.js dashboard that consumes `NEXT_PUBLIC_API_URL`.
- Runtime outputs under `var/` are intentionally not required for source reproducibility.

If Yahoo Finance or `yfinance` is unavailable, use:

```bash
.venv/bin/python -m trading_agent demo-summary --synthetic
```

This validates the strategy/dashboard pipeline with deterministic fallback data but is not evidence of real-market performance.

## Key Design Choices

- Use Python 3.9-compatible syntax unless the project says otherwise.
- Use JSON policy config to avoid startup dependency friction.
- Keep live trading disabled in config.
- Make the Schwab adapter prepare order payloads but raise `LiveTradingDisabled` before submission.
- Use SQLite for audit logging.
- Use FastAPI for the dashboard/API backend and Next.js for the primary product-style dashboard frontend.
- Keep Streamlit only as optional or legacy local research UI if present.
- Use Yahoo Finance adjusted close via `yfinance` for real historical demo data, cached under `var/market_data/`.
- Include deterministic synthetic prices only as fallback/offline validation.
- Make Yahoo refresh an explicit API/button action so normal UI interactions do not repeatedly re-download data.

## Modules

- `domain.py`: dataclasses and enums for account state, positions, order intents, strategy signals, risk checks, decisions, and prepared orders.
- `config.py`: load policy JSON into a typed policy object.
- `risk.py`: enforce kill switch, asset policy, order shape, loss limits, exposure caps, risk amount, and earnings-event checks.
- `recommendations.py`: size long orders from price/stop/risk budget.
- `storage.py`: audit event store.
- `backtest.py`: benchmark returns and summary metrics.
- `demo.py`: run ETF/equity/combined strategy demos over real historical prices, including simulated trade-history rows from rebalance weight changes.
- `data/yahoo.py`: cached `yfinance` adjusted-close downloader.
- `execution/schwab.py`: guarded order preparation and disabled live submission.
- `backend/app/main.py`: FastAPI app with CORS for local/deployed frontends.
- `backend/app/serialization.py`: convert pandas/numpy objects into JSON-safe dashboard payloads.
- `backend/app/routers/dashboard.py`: summary, strategy detail, and trades endpoints.
- `backend/app/routers/data.py`: explicit Yahoo refresh endpoint.
- `frontend/src/components/TradingDashboard.tsx`: Next.js dashboard with metrics, charts, policy status, trade filters, and CSV export.
- `dashboard/app.py`: optional Streamlit summary table, equity curves, drawdowns, weights, trades tab, prices, and policy view.
- `cli.py`: `show-policy`, `init-db`, `risk-check-sample`, and `demo-summary`.

## Example Strategies

- `50/50 SPY/QQQ`: primary benchmark.
- `ETF Equal Weight`: equal-weight sample ETF basket.
- `ETF Momentum Rotation`: monthly top-3 ETF momentum with trend filter and defensive fallback.
- `ETF Defensive Trend`: SPY 200-day trend risk-on/risk-off allocation.
- `Equity Momentum`: monthly top-5 volatility-adjusted stock momentum.
- `70/30 Combined Policy`: 70% ETF momentum and 30% equity momentum.

## Useful Tests

Cover:

- Policy config loads defaults.
- Risk engine allows safe ETF buys.
- Risk engine blocks leveraged ETF symbols.
- Risk engine blocks excessive risk.
- Risk engine blocks pre-earnings equity buys without exception.
- Risk engine allows reduced-size earnings override.
- Risk engine blocks short sale.
- Schwab adapter refuses submission while live trading is disabled.
- Demo backtests produce expected strategy rows.
- Buy-and-hold strategies emit only initial entries and final marks.
- Rebalanced strategies emit mid-period entries, trims, exits, and final marks.
- Combined policy trade history scales underlying sleeve rows.
- Backend health, policy, dashboard, strategy detail, trade, and CORS preflight endpoints behave correctly.
- Frontend typecheck and production build pass.
- Yahoo loader reads cached prices without network.
